  <files>src/db/manager.rs, src/db/mod.rs</files>

    - .planning/research/PITFALLS.md

  <action>
    Create `src/db/manager.rs` implementing `DbManager`:
    1. Structure:
       ```rust
       pub struct DbManager {
           conn: duckdb::Connection,
       }
       ```
    2. Methods:
       - `pub fn new_in_memory() -> Result<Self, duckdb::Error>`: Opens `duckdb::Connection::open_in_memory()`.
       - `pub fn execute_batch(&self, sql: &str) -> Result<(), duckdb::Error>`: Executes DDL or multi-statement scripts via `self.conn.execute_batch(sql)`.
       - `pub fn execute_query(&self, sql: &str) -> Result<QueryResult, duckdb::Error>`:
         - Measures duration using `std::time::Instant::now()`.
         - Prepares statement `let mut stmt = self.conn.prepare(sql)?;`.
         - Extracts column names and types from statement column count:
           Use `stmt.column_count()` and iterate to extract `stmt.column_name(i)`.
         - Executes `stmt.query_map([], |row| ...)` mapping row cells using `row.get_ref(i)?` (handling `duckdb::types::ValueRef` variants: `Null`, `Boolean`, `TinyInt`, `SmallInt`, `Int`, `BigInt`, `HugeInt`, `Float`, `Double`, `Text`, `Blob`, `Timestamp`, `Date`, etc. into `SqlValue`).
         - Computes `execution_time_ms = start_time.elapsed().as_secs_f64() * 1000.0`.
         - Returns `QueryResult { columns, rows, row_count, execution_time_ms }`.
         - For non-SELECT statements (DDL/DML like `CREATE TABLE`, `INSERT`) where no columns are returned, fall back to executing `self.conn.execute(sql, [])` and return an empty `QueryResult` with `row_count: 0`.
       - `pub fn list_tables(&self) -> Result<Vec<String>, duckdb::Error>`:
         - Queries `SELECT table_name FROM information_schema.tables WHERE table_schema = 'main' ORDER BY table_name;` and collects table names.
       - `pub fn describe_table(&self, table_name: &str) -> Result<Vec<ColumnMeta>, duckdb::Error>`:
         - Uses sanitized/escaped query `PRAGMA table_info(...)` or `SELECT column_name, data_type FROM information_schema.columns WHERE table_name = ?` to return `Vec<ColumnMeta>`.
    3. Update `src/db/mod.rs` to expose `manager` and re-export `DbManager`.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User SQL Input → DuckDB Engine | Arbitrary SQL text provided by user executed against embedded DuckDB |
| Native Thread → DuckDB Connection | In-memory database accessed by database manager |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Denial of Service | DuckDB Query Engine | medium | mitigate | Capture errors safely from `prepare()` and `query_map()` as `Result<QueryResult, duckdb::Error>` without unwrapping or panicking |
| T-01-02 | Information Disclosure | Schema Introspection | low | mitigate | Introspect strictly within the `main` schema / current connection catalog, preventing access to host OS or unauthorized internal tables |
| T-01-03 | Elevation of Privilege | SQL Query Execution | medium | mitigate | Run DuckDB in-memory without filesystem persistence or shell execution extensions enabled |
</threat_model>
